## Understanding
- Outcome: a consumer overrides any `--line-*` token or reset rule without fighting the cascade, whatever
  loads the CSS (`<link>`, a JavaScript import, `@import`) and whether or not the consumer uses cascade layers.
- Mechanism: for normal author declarations the cascade compares context (shadow tree), then layer, then
  specificity, then order (CSS Cascade 5 §6). `:where()` acts only on specificity. Every unlayered rule beats
  every layered rule, so a consumer override inside `@layer` loses to today's unlayered package rules at any
  specificity.
- Why the library ships the layer: CSS Cascade 5 offers two ways to place third-party CSS in a layer, an
  `@layer` block in the library or `@import url(…) layer(name)` in the consumer. HTML has no `layer` attribute
  on `<link>` (whatwg/html#7540, open since 2022-01, "needs implementer interest"), and a JavaScript CSS import
  has no standard way to name a layer. Only the library-side block reaches every consumer.
- Evidence (Chromium via Playwright, inline CSS that mirrors the package selectors):

  | Consumer scenario | Today (unlayered) | `@layer line` |
  |---|---|---|
  | Override outside layers in `:where(html)`, loaded before the packages | loses | wins |
  | Override outside layers in `html` | wins | wins |
  | Override in `@layer base` (Tailwind v4 convention) | loses | wins with `@layer line;` first |
  | Tailwind `mt-4` in `@layer utilities` on a `<p>` inside `.line-card`, with `reset.css` | loses (0px) | wins (16px) with `@layer line;` first |
  | Override in `@layer base`, `line` first appearing after the consumer's layers, no order statement | loses | loses |
  | Consumer `::part()` inside `@layer` against an unlayered rule inside the shadow root | wins | wins |

- Evidence (pipeline): the repo `postcss.config.mjs` turns `@layer line{:where(html){…}}` into the same text.
  The preset-env targets support cascade layers, so no polyfill runs. No document-level package declares
  `!important`, so the reversed `!important` order across layers sets no trap.
- Evidence (peers, checked 2026-10-12): Web Awesome 3 ships `@layer wa-theme` and `@layer wa-native`, Tailwind
  CSS v4 ships `@layer theme, base, components, utilities`, Panda CSS ships `@layer reset, base, tokens, recipes,
  utilities`, Mantine ships `styles.layer.css` in `@layer mantine` next to `styles.css`. Open Props 1 and Radix
  Themes 3 ship unlayered CSS.
- Stated (Miguel): option B, every rule of the three packages in `@layer line`.
- Stated (spec): `:where()` zero specificity (§6.C.2, §6.C.4), generated CSS committed to `src/` and never
  hand-edited (§6.C.3, §6.C.4), the Customisation guide covers the cascade strategy (§6.G.3).
- Assumed (orchestrator defaults, Miguel may correct):
  - The layer name is `line`, matching the `--line-*` token prefix and the `line-*` tags (T1).
  - One layer, no sub-layers. Sub-layers can be added later inside `line` without changing any consumer order
    statement. Only `reset.css` sets real properties, and the token, palette and role files declare disjoint
    custom properties, so order inside `line` decides nothing.
  - The `@layer line { … }` block lives in each `src/` leaf file, and the generators emit it. Barrel files keep
    only `@import` rules. The source, the built CSS and the generators then state the same contract, and the
    tests that read `src/` keep working.
  - Every `:where()` selector stays as it is. The packages declare no layer order statement of their own.
  - The `line-core` shadow-DOM reset sheets stay unlayered. The context step ranks consumer rules above them
    before layers apply.
  - The recipe for consumers reads: overrides outside `@layer` always win, and a stylesheet that declares
    layers starts with `@layer line;` or puts `line` first in its order statement.
  - One `patch` changeset per package (`docs/PROCESS.md` §6, Phase 00 after `0.1.0`).

## Public surface touched
- New public name: the cascade layer `line`. Consumers reference it in their order statements, so renaming it
  later breaks them.
- Every `--line-*` declaration and every `reset.css` rule moves into `@layer line`. Token names, values and
  selectors stay the same.
- Behaviour change: unlayered consumer rules now win at any specificity and in any order, and layered consumer
  rules win once `line` comes first in the layer order.
