## Understanding
- Outcome: the `deploy-site.yml` job that holds `CLOUDFLARE_API_TOKEN` runs no package lifecycle script and no
  build code, before `line-genui` adds `@a2ui/web_core` and its dependencies to the workspace install.
- Stated:
  - The Install step runs `bun install --frozen-lockfile` without `--ignore-scripts` in the job whose Deploy
    step holds the token and runs `bun x --no-install wrangler pages deploy dist` from `node_modules`.
  - AM-067 rejected `--ignore-scripts` in every workflow, `deploy-site.yml` included.
  - Plan O4.a names one option, two jobs with `--ignore-scripts` in the deploy job, the `deploy-storybook.yml`
    shape (AM-044).
- Observed on `ef91449`:
  - The §6.F.5 `deploy-site.yml` block (spec lines 2035–2073) matches the workflow file byte for byte.
  - `bun.lock`, `package.json` and `apps/site/package.json` are unchanged since `a92fc23`, so the AM-067
    evidence still holds. The default-trusted packages with install scripts are `esbuild` and `workerd`.
  - A clean `git archive` copy ran `bun install --frozen-lockfile --ignore-scripts`, the packages build and the
    site build, each with exit 0. `apps/site/dist` held `index.html` and `favicon.svg`, and
    `bun x --no-install wrangler --version` printed `4.148.0`.
  - `apps/site` holds no wrangler config file, so a deploy job with only the manifests loses nothing.
  - The `deploy-storybook.yml` deploy job already runs the locked wrangler after an `--ignore-scripts` install
    from a sparse checkout of the manifests.
- Assumed:
  - Build-time dependency code (Astro, Vite, PostCSS plugins) running in the same job as the token is part of
    the exposure the row targets, because it can rewrite `node_modules/wrangler` just as an install script can.
  - The workflow cannot run before merge (push to `main` only, `site-production` allows `main` only), so the
    first real run is the merge of this PR.

## Decisions

| Fork | Decision | Rejected |
|---|---|---|
| Fix shape | Split `deploy-site.yml` into a `build` job and a `deploy` job, the `deploy-storybook.yml` shape. The `deploy` job installs with `--ignore-scripts` (Miguel, 2026-10-13) | `--ignore-scripts` in the single job; the split with `--ignore-scripts` in both jobs |
| `build` job (orchestrator default) | No `environment`, no secrets, `contents: read`. Keeps the plain `bun install --frozen-lockfile`, builds the packages and the site, and uploads `apps/site/dist` as the artifact `site-dist` with `if-no-files-found: error` and `retention-days: 1` | — |
| `deploy` job (orchestrator default) | `needs: build`, `environment: site-production`, `contents: read`. Sparse checkout of the five manifest paths `deploy-storybook.yml` uses at `github.sha`, `setup-bun` with `no-cache: true`, `bun install --frozen-lockfile --ignore-scripts`, download `site-dist` to `${{ runner.temp }}/site-dist`, then the locked wrangler deploys that directory from `apps/site` | — |
| Action pins (orchestrator default) | `actions/upload-artifact` and `actions/download-artifact` use the same SHAs and versions as `deploy-storybook.yml` | — |
| Scope (orchestrator default) | No deployment-URL summary step; the project name, branch, commit flags, triggers and concurrency stay as they are | — |
